7.RAG(Retrieval Augmented Generation):- Providing external Knowledge and real-time information to get more accurate result and reduce hallucinations
MODELS are trained on data which has cut-off dates i.e. models do not have any information about your company’s docs or may be what happen last week
You want model to work with company files. Research paper, experiments, Confidential files etc. You can dump all your data as models have context window


So we want model to retrieve data as and when its required.

HOW RAG works
Step1- Indexing
Bring all your files(PDfs, Documents, DB)
 Split them into smaller chunks
 Each chunk is converted into Numerical Vector (index) using defined Embedding Model
            Vector is like mathematical fingerprint of the chunk(piece of text)
            Vector DB is Organized, searchable and ready to retrieval 

Step-2 Retrieval:-
      User ask question
     Question converted into vector using same embedding technique
    Now using question vector; searches into vector Db to search for similar/matching chunks(using probability of matching) 
Pull most relevant(matching) chunks

Step-3 enumeration:-
Using Relevant chunks ; inject them into LLM prompt alongside user question
Instruct to LLM like “Answer this question based on this context”
LLM has all information needed in its context itself so 
Genrates accurate, Grounded  and reliable answer

RAG- Combines Information retrieval with LL generation so model can answer based on your specific data

NO Hallucination about things he doesn’t know
NO Outdated answer
NO I don’t have access to that info/data
JUST ACCURATE ANSWER BASED ON YOUR ACTUAL DATA.

CHUNking is most imp thing in RAG system
If chunk is too small- loss of context
                       Large – imprecise retrieval

Technique as HIerarciecal Chunking
Small chunks for precision as child
Large chunk for more information(accuracy) as parent chunks
Precision(child)+Context(Parent=Better Retrieval

User Query  Retriev ContextLLM Answer

**Agentic RAG= Instead of fixed pipeline agent decides when and what to retrieve dynamically; executes its multiple rounds till get required info
MOST POWERFUL PATTERN FOR COMPLEX MULTISTEP RESEARCH TASKs.

Vectors in High-dimensional space
Meaning as direction
Numbers that capture semantics
Similarity through Distance(Cosine cone)
Fondation for search and retrieval
To power AI application

Vectors and embeddings
Embedding is way to represent meaning as number
Long List [0.21, -0.44, 0.13, 0.87, 0.01, …] is called as Vector
Similar Meanings Get Similar Numbers
Happy joyful [0.21, -0.44, 0.13, ..]
Sad Unhappy [-0.22, 0.45, -0.12..]
Close numbers are -0.44 and 0.45

e.g. puppy and dog and up as vectors that are very close to each other in mathematical space

Cat is bit far but in neigrhood while bus is in diff direction from it
MODEL LEARNS to Organize its CONTEXT into its meaning iin giant Numerical space

Because of this now we can
Find Documents that are conceptually related to a question even if they use completely diff word.

Like Benefits of dogs for kids ?
Emotional impact of animal companionship  or
Why children bond with pets

11.Agentic Architecture:- How we structure agent’s thinking as diff. problems needs diff approaches and solution

These patterns are nothing but agentic architecture
A.	ReAct= Reason->ACT-> Observe
 Works for most General tasks

B.	Chain-of-Thought = Question-step1-ste2-step3-Answer
-	Forces model to give entire reasoning process b4 giving an answer
-	E.g in prompt we are saying lets think step by step
-	Improves Accuracy in Maths problem, logic puzzles and multi-step reasoning

C.	Plan and execute;-
-	Creates a complete plan upfront then it execute each step one by one
-	Good for predictable workflows, we know what happens in next phase or execution
 Something happens mid execution upfront plan might be outdated

D. Tree of thoughts:-
      Instead of one line of reasoning Agent explores many paths in parallel(multiple branches simultaneously ) to get solution 
Like chess player- considerin several moves at once then evaluating which branch looks most promising ; execute that only

This architecture great for Creative and strategic decisions
Highly expensive(in terms of compute) but better solution for complex problem

E. Reflexion:- SELF IMPROVEMENT THROUGH FAILURE
Agent tries task if its failed/ imperfect result then explicitely reflect on what and why  went wrong and tries again by keeping that reflection in mind.
Great for coding tasks, Maths or anything verifyable

F.LATS(Language Agent Tree Search)= combination of Tree search+ React+Reflexion
Explores tree for possible actions
Evaluate each branch
Learn from failure

Its very expensive, complex but highly powerful(high stakes optimization problems)

** Production systems uses ReACT+ Relxion
Simple, reliable and powerfull
